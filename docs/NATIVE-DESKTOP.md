# Native desktop foundation

## Acceptance and limits

The approved first vertical slice is an installed Omarchy desktop app that opens local audio, loads a deck and actually plays, pauses and seeks through the default output, retaining all five views and shared state.

The implementation is a **Linux preview**. Source, native signal output and desktop integration can be tested independently of the target desktop. User-local installation and launch through the normal desktop entry have now been verified on the Omarchy target, including a native Wayland window, the new library controls, retained private library and an audio-ready engine. The presentation-only deployment preserved the newer import/library backend byte-for-byte, retained the saved library and restored paused. These are launch/readiness smoke tests, not full file-chooser/portal, physical audible output or hardware-latency acceptance. Other operating systems and professional-DJ parity are not claimed.

Supported controls: import a local source, load A/B/C/D, play/pause, seek, manual cue positions, per-deck input gain, three-band full-kill EQ and bipolar sweep filter (see "Channel strip"), channel levels, stereo peak meters and independent L/R/THRU crossfader assignment (C/D default to THRU). Tempo (±8%), pitch lock, detected constant beat grids and explicit master/beat-phase sync are implemented for local audio (see "Analysis and tempo processing"). Time stretching runs on the preparation worker before the channel strip, so EQ, filter, fader, meters and the crossfader always act on the tempo-processed signal, and every channel's source clock stays the consumed source frame. Master headroom is deliberately conservative (0.25 before the channel level); this is not a calibrated loudness or limiter implementation. FX, loops, key detection, headphone cue routing and hardware mappings are disabled/unimplemented.

## Channel strip

`native/src/dsp.rs` wraps each deck's device-facing `PcmSource` in a `Strip`. Per deck, a lock-free `DeckControls` (relaxed atomics: five knob positions as f64 bits, the linear fader gain and a "snap" flag) is written by the control thread and read by the audio iterator once per 32-frame block. It outlives every loaded source, so settings survive load, seek and natural-end restart; a new source starts at the stored targets without gliding from defaults. Nothing runs on the decode worker (that would add up to the half-second ring length of control latency), and the ring/retirement mechanism of `stream.rs` is untouched: dropping a `Strip` drops its `PcmSource`, which releases the consumer first.

Signal path: phase-aligned LR4 three-band split (250 Hz / 2.5 kHz) → band gains → sweep filter → trim/channel fader → native stereo peak meter → crossfader/master headroom → per-deck safety bound. The crossover has flat neutral magnitude with phase rotation. Each band at zero contributes exactly zero; all-band kill settles to digital silence. Band overlap remains near each crossover.

GAIN remains −12…+12 dB. Nonzero EQ values retain the nominal −24…+12 dB taper with 50 neutral; zero is a separate full-kill endpoint. The bipolar sweep filter is unchanged and bypasses exactly at 50. EQ and output gains use short smoothing ramps; gain/filter keep their block smoothing. Paused edits snap on resume. A new stream retains the 2 ms fade. Fixed per-channel state and atomic targets/meters add no callback allocation, lock, I/O or decode work. Existing bounded source-frame/underrun accounting and off-callback retirement remain authoritative.

Five exact semantic commands gain/hi/mid/low/filter retain bounded values, with assign adding an exact deck and left/right/thru side. Snapshots carry bounded channel meters and assignment. The renderer adopts settings only after successful saved mixer restoration, validates telemetry, discards deferred gestures on failure and never auto-replays transport. Label kill memories and routing persist through the existing store. Meter elements are cached with the transport painter; ordinary clock frames do not query or rebuild the library/header.

Meters are actual stereo peaks after channel processing and before the crossfader. Paused, ended, failed and disconnected channels report zero. This remains an engineering mixer, not a hardware-calibrated analog VU/loudness meter, limiter or latency guarantee. FX, headphone cue and master EQ remain unavailable.

## Authority boundaries

- `desktop/main.cjs`: owns the single app window, native file selection, private library, native child and allowlisted IPC.
- `desktop/policy.cjs`: admits exact semantic request shapes only, from the intended main frame at the exact app URL. It does not expose paths, shell commands or arbitrary engine commands.
- `desktop/preload.cjs`: context-isolated, sandboxed bridge. Node/process/Electron APIs are not exposed to page code.
- `desktop/library.cjs`: selected-source registry, opaque UUID IDs and descriptor identity. Absolute source paths live only in private user-local state; renderer metadata contains basenames, IDs and audio properties. Atomic library writes use mode 0600; application storage is mode 0700.
- `desktop/importer.cjs`: bounded multi-file/recursive-folder import, private source validation, deduplication, progress and sanitized failure summaries. A one-shot `--inspect` invocation of the native binary decodes metadata without opening an output device or modifying a deck. All file arguments originate from OS selection, not renderer paths. Waveform generation still occurs when a track is loaded.
- `src/library.js`: real local-library controls, crate/playlist views, selection, ordering and semantic collection commands. The private registry owns durable collection content; `src/store.js` remains the sole renderer snapshot writer for view/sort choice. Demo fixtures are separate and non-playable in the desktop library. Playlist order does not imply automatic playback.
- Selected local sources are retained through exact semantic `retain-track` IPC (deck plus known opaque track ID), before checking native output readiness. The bounded main-process references survive child reconnects and protect renderer-selected sources even when native deck snapshots are empty. This does not load or play audio. Renderer removal guards and atomic catalog validation independently prevent selected decks losing their metadata.
- `desktop/audio-client.cjs`: explicit native executable, positive operational environment allowlist, bounded JSON-line frames, request correlation, generation/sequence validation, disconnect handling and a heartbeat watchdog. No network listener or automatic command replay.
- `native/src/main.rs`: audio/transport authority. Four decks, transactional staged loads, per-deck load ownership, bounded preparation admission, native sample-frame positions and acknowledgement snapshots.
- `native/src/dsp.rs`: per-deck gain/EQ/filter/fader strip over the device-facing iterator (allocation-, lock- and I/O-free after construction), the knob-to-dB/Hz mapping and its tests.
- `native/src/stretch.rs`: streaming waveform-similarity time stretch / linear resampling on the preparation worker only (allocation happens there, never on the device callback); it labels every produced sample with its source-frame position and feeds the bounded queue that `stream.rs` owns.
- `native/src/stream.rs`: file reads/decoding/seek preparation on workers; bounded SPSC PCM queues to the device-facing iterator. Empty queues output zero without advancing media position, while underrun counters record the event. Buffer destruction is retired off the device-facing iterator. Rodio/CPAL still has its own internal machinery; this is not a claim of hard-real-time certification.
- Waveform data: after each `load`, a native worker thread (never the device-facing iterator) decodes the file once and emits one `waveform` frame. It carries the persisted 512 peaks and a session-only `detail` envelope: `bins` = ceil(duration × 64) clamped to 512–32,768, plus base64 8-bit `peak` (largest absolute sample in the bin) and `rms` per bin, measured from the decoded PCM with no interpolation. `desktop/library.cjs` `publicWaveDetail` accepts only the exact shape (canonical base64, exact lengths, RMS ≤ peak); The snapshot’s `waveGeneration` identifies the source-load analysis and stays stable across seek/replay stream preparations (`loadGeneration` changes for those). `desktop/main.cjs` rechecks source/engine/deck/wave ownership after persistence and forwards it as a separate `waveform-detail` renderer event and never writes it to the registry, so the 16 MiB library budget and 512-peak record format are unchanged. The frame stays near 90 KiB at most, far below the audio client's 256 KiB unframed-output limit. `src/catalog.js` keeps at most eight envelopes in memory and drops them with their track; `src/wave-render.js` samples the displayed interval at device-pixel resolution (up to 4,096 columns; maximum for wide columns, so transients survive; the bin's own value for narrow ones) and paints a canvas. Resolution limits: about 64 bins/s up to ~8.5 minutes, coarser for longer tracks; values below about −54 dBFS (half an 8-bit step) round to silence; mono peak/RMS across all channels, not frequency bands. Seeks and replays do not re-analyze.
- `src/native.js`: maps accepted native receipts to the shared UI model. Old replies cannot rewind state or resurrect an old engine; a newer Pause supersedes an asynchronous Play preparation. Layout renderers never start another backend.
- `src/mixer.js`: pure knob labels (dB, Hz, spoken text); it describes the engine's mapping but never models audio.
- `src/store.js`: sole renderer snapshot owner. Live positions are checkpointed; explicit paused seeks and transport changes persist immediately. Reopening always restores paused.

### Scrubbing and transport painting

The console's existing wheel viewport remains presentation authority: `src/wave-zoom.js` shares its 1×–32× scale with the new +/− controls and `src/wave-input.js` captures its actual seconds-per-pixel mapping at pointer-down. Native decoded peak/RMS detail, pixel-aligned canvas painting, timeline click seeking and unzoomed overview controls remain intact. No obsolete layout or theme is restored by the scrubbing integration.

`src/scrub.js` supplies pure geometry and a latest-target queue with one seek request in flight. Playing drags submit interim targets at most every 90 ms; release submits the final target as soon as the outstanding request completes. Paused pointer drags preview until release. Native seek acknowledgements and consumed media frames remain authoritative; failure or superseding ownership clears the transient view immediately. Pointer/touch cancellation, hidden windows, focus loss and view replacement drop queued targets.

`src/frame.js` caches transport elements and canvas geometry/theme metrics between cold updates. Ordinary native receipts repaint changed accepted positions, channel-strip values or the explicit gesture preview; they do not query or reorder library rows, rebuild markup or extrapolate positions. Native playback snapshots have a bounded 16 ms interval, preparation-only snapshots 50 ms and idle snapshots 250 ms; the native loop blocks until input or the next deadline and adds no work to the device-facing PCM iterator.

`node scripts/scrub-browser-test.mjs` exercises real Chromium pointer/touch/keyboard input with a clearly mocked native bridge and measures rendering cost using independent animation-frame samples. The actual signal suite measures playing cadence, fractional seek acknowledgements and resulting PCM; the Electron lane sends real pointer input through renderer, IPC and native seek. These are controlled fixtures, not physical-output latency or target-desktop frame-rate acceptance.

Before native decoding, regular-file type and selected descriptor identity are checked (device, inode, size, modification time). Nonblocking opens prevent a substituted FIFO from hanging before validation. Changed/missing/unsupported sources are rejected instead of silently replacing another deck. Input size, duration, channels, sample rate and control values are bounded.

The app window uses a private app scheme, hash-authorized script CSP, denied external requests/permissions/navigation/popups, no webviews and no renderer Node integration. The desktop has no HTTP server, telemetry or cloud library sync. Selecting a file on an OS-mounted network drive still uses that filesystem; the app does not upload music.

## Analysis and tempo processing

The one-shot identity-bound inspector decodes at most 60 seconds for a bounded onset envelope and estimates a 60–200 BPM constant beat grid. Low confidence, silence and short material produce no grid. The same analysis runs off the audio callback after load; legacy saved tracks can be analyzed explicitly without reimport. Grid offset is an onset anchor, not a classified downbeat. Native sync requires both grids, an explicit master and a resulting rate within 0.92–1.08. It compensates master source-clock movement at the prepared-source commit, rejecting a changed master or insufficient prepared data instead of claiming alignment.

The producer worker (`stretch.rs`) performs linear resampling when pitch lock is off and waveform-similarity overlap-add when on, before PCM enters the ring; the device-facing channel strip (`dsp.rs`: gain, EQ, filter, fader, meters) runs afterwards and sees only tempo-processed audio. All channels share one alignment offset. Each queued PCM sample carries its consumed source-frame position; callbacks consume only bounded ring data and update atomics, so source clocks stay correct through rate changes and underruns. The nominal queue capacity is 100 ms; analysis, decode, stretching and resource retirement stay off callback. This is a basic stretcher with possible transient artifacts and no hardware latency guarantee.

Pitch lock/rate are native-owned acknowledged settings. Renderer gestures coalesce, retain source ownership and cannot replay after reconnect. Restore loads paused, restores rate/lock and source positions, then the selected master. Sync preserves pause/play and follows master tempo changes; separate transport actions require resynchronization.

Embedded artwork is probed under bounded tag/image limits and only JPEG/PNG is decoded, with a 2 MiB encoded-size and 2048×2048 dimension ceiling. It is reduced to a 64×64 RGB PNG with tags removed before renderer delivery. BPM, grid, analysis version and thumbnails use the existing private atomic registry and shared 16 MiB capacity limit. Renderer metadata and data-image CSP remain path-free; no external artwork request is allowed.

## Packaging and installation

`npm run build:desktop` builds the offline UI and native release engine, remapping builder-home compiler paths. `npm run package:desktop` requires reviewed clean source and emits a small application/native-engine archive plus SHA-256. Its manifest records source commit, file hashes/modes, installer hash and the exact official Electron runtime URL/hash.

The installer verifies package files and the runtime ZIP, extracts into an owned staging release, creates user-local launchers and switches `current` atomically. Prior releases remain available for rollback; it does not delete music, change OS volume, install system packages, create a system service or restart an existing copy. Runtime ZIP entries, package paths and existing launchers are checked before use. Dependency notices are preserved.

User state is never included in a package. Packaging uses an explicit runtime-source/asset allowlist rather than copying a working directory with ignored logs or audio files.

### Library persistence capacity

Both writing and restoring enforce at most 10,000 records and 16 MiB of serialized UTF-8 JSON. The byte limit includes paths, metadata and the decoded 512-value waveform arrays, not just track count. Snapshot construction stops at the byte budget before opening a temporary file; restoration bounds the actual read as well as checking file size. Waveform amplitudes retain their decoded resolution. Only known private record fields are persisted; paths never enter renderer metadata.

Collections share this byte budget and are bounded to 200 named collections and 20,000 memberships in total. Each has an opaque ID, kind, bounded name and unique ordered local-track IDs. Crates group tracks; playlists expose explicit up/down order controls. Registry-only removal cleans memberships without deleting music. Loaded/loading sources are protected from removal. Collection edits and library removals restore their previous in-memory state if the atomic write fails. Prior version-1 files without collections still restore. Pre-0.3 apps ignore collections and can drop them on their next save; retain a private state backup before such a rollback.

An import scans at most 20,000 entries and admits at most 1,000 candidate files, with bounded recursion and no symlink following. Inspection is sequential, times out after ten seconds per file, has bounded stdout and does not inherit account/credential environment. Failed candidates do not become durable tracks. The import response replaces the renderer catalog with the **whole** library, not just the current batch, so existing deck references remain valid. Output-unavailable operation is deliberate: files/collections can be managed while transport remains disabled. This does not prove the native binary is present or functional in a different installation.

An oversized metadata/waveform update or import returns a failed save with a capacity warning through the existing desktop warning path. It remains usable in memory for this session but does not replace the previous saved registry. A later snapshot within budget may save normally. Successful writes still use a private temporary file, file sync and atomic rename; save failure does not erase the previous durable file. Existing version-1 libraries within these limits remain supported. An already-oversized legacy file is not automatically repaired or deleted; restoration reports failure, and recovery requires a separate deliberate backup/re-import decision.

### Manual uninstall

Follow the [checked manual removal instructions in README](../README.md#uninstall-keep-music-and-preferences). Quit the app first and avoid concurrent installation or rollback. Verify the managed-root marker and both managed launchers, including their targets and lack of unexpected symlinks, before removing anything. Remove only the managed `~/.local/share/deck-craft/` root, `~/.local/bin/deck-craft` and `~/.local/share/applications/deck-craft.desktop`. Stop if they contain unrelated/custom data or do not match the installer. Music is never an uninstall target. Private user state is intentionally retained, and no system packages/services are removed. Rollback is not uninstall.

### Deliberately remove private user state (optional)

This is **separate from uninstall**, not a default cleanup step. With Deck Craft fully closed, first back up any preferences/session/library registry you want to retain. On Linux the production app explicitly uses the `deck-craft` subdirectory of Electron's application configuration directory: normally `~/.config/deck-craft/`, or `$XDG_CONFIG_HOME/deck-craft/` if that variable was set when the app ran. A development/test launch may explicitly override user data; do not guess or delete a test/custom directory as part of production uninstall.

Inspect the exact real application-state directory in a file manager, confirm ownership and contents, and stop on unexpected symlinks or unrelated files. Only after deliberately deciding to discard the library registry, preferences, cues and saved session, delete that specific `deck-craft` state directory, **not its parent configuration directory**. This removes the private `library.json` path/opaque-ID registry and Electron's stored renderer session/preferences/cache. Saved opaque IDs cannot be recovered without a backup; importing music again creates new IDs. Do not delete the files named inside `library.json`: those are original music sources, not application-state files. State deletion does not delete music or remove an installed app.

## Executed verification

The development gates include actual generated WAV, MP3, FLAC, Ogg Vorbis, AAC/M4A, ADTS AAC, AIFF and ALAC/M4A decode/paused-seek checks. Recoverable driver notices (XRuns, real-time promotion refusal, already-rerouted default output) do not masquerade as a disconnected device; genuine invalidation/disconnection remains fail-closed.

## Isolated Linux test-driver prerequisite

Older ALSA PulseAudio plugins (including the stock 1.2.12 test transport) compare the negative `pa_stream_get_latency` error with positive `PA_ERR_NODATA`. That can turn temporarily unavailable timing into `snd_pcm_avail_delay` I/O errors during startup. Use a transport containing the [upstream negative-error comparison fix](https://github.com/alsa-project/alsa-plugins/blob/master/pulse/pcm_pulse.c) for the isolated null-sink lane. Driver-only paired runs reproduced failures with the old plugin and passed with the source-built fixed plugin, without changing the installed app. This is a test dependency, not an application-bundled driver; no system audio configuration was modified and genuine output errors remain fail-closed. A passing patched-fixture test does not replace actual Omarchy/PipeWire/physical-output acceptance.

The development gates include:

- Model, persistence, view-fidelity, IPC authority, private library and stale/native-owner regression tests.
- Native protocol/validation and actual PCM decode tests in Rust.
- User-local install/update/idempotence/rollback and invalid-payload/runtime/path/launcher tests in Python. Those safety unit tests deliberately use tiny fixture archives; they are not app execution evidence.
- Real native signal integration through an isolated Unix PulseAudio null sink: generated WAV decode; advancing native frames; pause; seek from a 440 Hz region to an 880 Hz region verified from captured PCM; real crossfader mute; natural end/restart; rejected corrupt replacement; unchanged other decks; waveform peaks; process death causing measured silence and no replay.
- Actual Electron window/bridge with the native engine: 25 layout transitions retain the same playing source/generation, manual cue/seek/pause, independent second-deck load, and full application restart restoring local source IDs/positions/cues/layout paused. Renderer Node/process access, extra IPC fields and arbitrary commands are rejected.
- The default Electron lane also uses real native inspection for files/folders, checks uninterrupted playback during import, duplicate/corrupt reporting, create/rename/delete collections, membership and playlist-order edits, retained original sources, full collection restoration and an explicit output-unavailable import phase. Only OS selection is injected. The optional real-chooser lane retains its prior single-file scope and lifecycle caveat below; it does not claim automated multi-file/folder chooser acceptance.

- Rust unit lane: analytic/measured frequency response of every EQ band and both filter sides at 8, 11.025, 22.05, 44.1, 48, 96, 192 and 384 kHz, flat neutral magnitude and phase-aligned band summation, channel independence, per-deck isolation, smoothing without overshoot or steps, finite bounded output under extreme settings with up to 32 channels at the extreme rates, strict command schema, unchanged stream position/underrun/retirement behavior through the strip, and the stretcher's pitch/clock/stereo-coherence tests.

### Native test setup

`npm run test:native` expects `ALSA_CONFIG_PATH`, a `PULSE_SERVER` Unix socket, and `DECKCRAFT_TEST_PAREC` pointing to the capture tool. The configured server must provide the isolated `deckcraft_test` null sink and monitor. No physical device is chosen implicitly. `DECKCRAFT_TEST_ENGINE` can select the release binary; `DECKCRAFT_EVIDENCE_DIR` keeps reports/captured data outside public source. Do not run signal and desktop suites concurrently against the same sink.

`npm run test:desktop` additionally uses Xvfb, Python 3 and a private D-Bus daemon. Its default injects only the OS file-selection result; all native file validation, decode, audio state, UI controls, persistence and restart are real. Set `DECKCRAFT_TEST_NATIVE_DIALOG=1` to automate the actual GTK chooser with xdotool. No test unmounts or repairs an existing filesystem.

### Environment caveat from the real chooser test

The real GTK chooser successfully selected generated audio, and the native UI loaded/played/paused/sought it across all layouts. Clean shutdown of that optional lane was blocked by an existing unrelated unresponsive FUSE/network filesystem during GTK volume discovery. Subsequent full restart tests used explicit fixture selection and passed; this distinction must not be erased or described as full native-chooser lifecycle acceptance. The existing mount was not changed. Operational diagnostics/process identities are private and excluded from this repository.

The actual Omarchy target has passed installation/native-Wayland launch and audio-readiness smoke checks. Full native file-chooser/portal interaction and physical-output checks are still required. Virtual-sink results and an audio-ready engine are not proof of speakers, interface routing, controller support, low latency or professional reliability.
