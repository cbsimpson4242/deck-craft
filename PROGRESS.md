## Reviewed waveform candidate before compact-header integration

User report: zoomed waveforms were a few thin vertical lines with black gaps (one deck) and a solid orange block (a compressed master). Reproduced with generated data in real Chromium (a regression that failed on the unmodified source: only 24–28% of pixel columns had ink at 32× in a 400 px waveform).

Root causes: (1) the whole track was drawn once as 2,048 fixed-width strokes in an SVG that wheel zoom stretched up to 32× horizontally, with non-scaling 1.15 px lines, so at 32× each stroke was separated from the next by several empty pixels, more as the box widens; (2) the only data was 512 peaks per track, about one value per half second of a four-minute track, linearly interpolated, and a limiter-flattened master has near-constant peaks, so its outline is a full-height block.

Fix: waveforms are now painted on a canvas for the displayed interval only (`src/wave-render.js`), one column per device pixel, sampled by maximum when columns are wider than the data and by the bin's own value otherwise; digital silence draws nothing and start/end of the track are empty. The native engine's existing post-load decode also emits a session-only finer envelope (about 64 bins/s, max 32,768 bins, 8-bit peak and RMS per bin) measured from the decoded PCM. The RMS draws the lighter inner core so compressed masters keep visible structure. The persisted record is unchanged (512 peaks; no new library growth), the renderer keeps at most eight envelopes in memory, and a deck without one falls back to the persisted peaks (smoothly interpolated for display, coarse at deep zoom). No new analysis claim: colors remain amplitude-only; cue flags, playhead, seek bounds, wheel zoom, themes, canvas views and the creator preview keep their previous mapping.

Independent review strengthened canonical base64/RMS validation in the renderer, bounded cache retention even with excessive protected IDs, and closed stale-forwarding races across asynchronous registry saves, same-track reloads, child death and reconnect. Native snapshots now distinguish source-wave ownership (`waveGeneration`) from the stream-preparation `loadGeneration` that advances on seek/replay. That preserves valid detail through paused restoration without accepting detail from a replaced source. Valid native detail may be cached before a delayed load reply selects its track; it cannot select a deck or start playback. Twenty-five focused regression tests pass on this reviewed source, including source/engine/load identity, same-track multi-deck use, early detail, frame/base64/persistence bounds, silence/transients, canvas sampling and seek mapping.
